# D2：本机热座

基于 `main` 的 D1 合并提交 `331aa86`，按 [联机 PRD v1.1](../PRD-online.md) 实现 D2。本期在同一个浏览器页面中模拟 2–4 名操作者；不创建房间、不联网。

## 使用

1. 打开 `game.html?hotseat=1`。在顶部「分配角色」中选跑团或合作配置，填写操作者名、主持人、每名角色归属，应用分配。可以先收起面板进入跑团/战斗准备，用现有队伍配置调整人数。
2. 跑团中一人可有多名角色，未分配角色由主持人代操作；合作配置要求每名操作者恰好一名角色。武器人继承主人的操作者，单独占格。支援伙伴和无角色归属的召唤物不可直接操作。
3. 房主开始战斗。回合开始效果结算后，通过顶部切换当前操作者，各自给全部单位选格并确认。选序不限时；占格先到先得，全员确定前可改选或使用明确的互换操作；房主可用「按当前格子开始」补齐空位。
4. 轮到某单位时切换到其操作者。技能、分步选择、移动、起身和道具仍用现有战斗界面；「结束单位行动」只结束该单位，所有单位结束才进入敌人回合。
5. 未实际消耗行动点/附赠行动的单位可以调序。拖动顺序格或用左右/末尾按钮；空位直接移动，同主人直接互换，跨主人需对方同意。跑团主持人可直接调整。目标必须位于所有固定格之后；移动不挤动固定格，原位置可留下空格。
6. 格挡或协助询问时切换到符合条件的操作者回答。每名操作者只看到自己的候选单位；先到的合法同意生效。全部放弃或 20 秒到期继续结算。绯秋的选刀合并在本人选项中；柯尔特的开局/切刀选择由本人完成。

实际扣点后即使同指令返还点数也锁定；选择技能、预览、取消不锁定。现有免费起身、免费协助攻击、掩护免费格挡仍然免费。倒地但可以起身的角色保留顺位；永久死亡或不能恢复者旁观。武器中途上场追加队尾，离场移除；同一回合重新唤出，按主人角色和武器种类保留已支出/已完成记录。

聊天只用于战前和选序协商。热座禁用战斗、规则层及探索撤销；普通 URL 下单机行为保持原样。会话配置和顺序只在内存中，刷新后重新分配，现有存档格式不变。可同时加 `&debug=1` 导出 JSON 指令日志。

## 模块边界

- `hotseat.js`：无 DOM 的单位归属、回合顺序、交换请求、实际支出、协助竞争/超时、文字协商，以及 `LocalTransport`。
- `hotseat-authority.js`：连接绑定操作者；协议/构建版本检查；指令编号去重；校验后只在房主运行一次规则，按收件人生成独立显示副本。客户端不能用消息中的 `sender` 冒充操作者，也不能用收到的状态重新结算规则。
- `hotseat-validation.js`：归属、当前顺位、阶段、行动预算、技能可用性、分步选择、目标/射程、移动与道具校验。遗留读取函数会规范化资源，因此在临时克隆状态上做预检，拒绝时恢复原引用和数据，不掷骰或执行技能。
- `hotseat-game.js`：连接既有 `dispatch`、完整规则状态和本机客户端。内部阶段推进与反应结算使用可信上下文，客户端只发送 JSON 指令。`endTurn` 在热座结束单位顺位；原单机仍结束整个我方回合。
- `hotseat-ui.js` / `hotseat.css`：只读取显示投影、发送操作，支持桌面拖动与手机按钮。`game.js` 接入既有技能/演出、开局选择、反应询问与单位轮转。
- `app.js · onActionSpend`：记录实际正支出，包含同指令退款前的支出和直接扣除附赠行动的既有路径；预演不写入热座记录。

顺序指令：`orderPick`、`orderConfirm`、`orderStart`、`orderMove`、`orderSwapAccept`。询问与协商：`answer`、`chat`。动作继续使用 D1 的 `skill`、`move`、`standUp`、`useItem`、`startCombat`、`endTurn`、`retreat` 等。`orderMove` 的 `index` 从 0 开始，行动中可等于当前格数，表示新增尾部空位。
