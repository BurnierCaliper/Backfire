## 交付清单

- [ ] 2–4 人包含房主，每人选一名不重复角色；人数决定原单局队伍与物资。
- [ ] 房主操作共同决策，其他玩家可以提出全员可见的建议；建议不执行规则、不扣资源，旧建议随决策失效。
- [ ] 升级由当前待选角色本人决定，房主不能代选；待升级时阻止其他推进和花钱操作。

- [ ] 开局后固定座位，只允许原座位恢复；永久死亡后保留旁观席，不补人换角。
- [ ] 房主在现有 SaveStore 保存联机标记及单局，独立恢复数据保留完整战斗、固定座位、归属、决策版本；客户端仅存自身凭据。
- [ ] 房主刷新及重新开房继续原局，原玩家恢复原座位；不把同名玩家当作原身份。
- [ ] 2–4 人完整第一幕、越权拒绝、30 秒断线、战斗中恢复、隐藏信息和全部决策入口回归。
- [ ] 完整 `npm test` 与 `npm run test:ui`；不同设备和手机验收；README 规则改动记录置顶，大文件不入库。

## 现有入口与权限

复用 `rogue-commands.js`，不复制 `rogue.js` 规则。`rogue-ui.js` 的现有按钮绑定是入口清单的依据。

| 权限 | 现有入口 |
| --- | --- |
| 房主最终决定，其他人建议 | `acceptTask`、`chooseNode`、`restAtNode`、`shortRestBeforeNode`、`camp`、`buy`、`introduceSmith`、`upgradeWeapon`、`claimBlueprint`、`installBlueprint`、`repairWeapon`、`healHero`、`modifyHero`、`attemptCheck`、`skipCheck`、`leaveNode`、`nextAct`、`afterVictory` |
| 当前升级角色本人 | `choose {kit,index,value}` |
| 房主进入战斗 | `run.session/startBattle` |
| 可信结算与保存回调 | `finishBattle`、`save`、`finishRun` |
| 房间内部生命周期 | 选角、新局、恢复、离开；不开放整个 `run.session` 接口给网络客户端 |

现有商店没有卖出入口，D4 不新增卖出或幕间玩法。单人模式及其第二副职责、伙伴支援不纳入合作联机。

## 实现时必须处理的边界

1. **查询也可能改状态。** `run.query` 的部分接口会生成内容，`restPlan/watchOptions/canShortRestBefore` 等还会经 `withParty` 重新准备战场；`heroView`、`cyberInfo` 包含完整角色信息。查询只在房主合适阶段串行执行，转换成明确允许的显示字段和操作选项，不能让客户端渲染原 `Rogue` 对象或执行查询。
2. **房主身份不是主持人权限。** D3 的 `OnlineView` 对 GM 整包放行，`OnlineGame.getView` 给房主完整状态，原联机 UI 挂载主持人消息。D4 要按模式分开：权威对象仍仅房主保存，但合作房主自己的显示也走脱敏路径；旧后台、跑团、`gm.*` 指令均不可绕过合作限制。
3. **校验当前决策。** 原规则有部分阶段限制由单机 UI 提供，不能只复用弱参数校验。房主需校验身份、阶段、待升级、当前可选商品/角色/工匠、严格参数及决策版本；拒绝旧索引、旧建议和伪造升级。
4. **战斗恢复不等于重开。** `RunFlow` 当前仅暴露 `start/resume`，需要可信适配接口。D3 快照尚未记录 `G.rogue` 的返回回调与撤退限制；恢复应重绑这些信息，不调用 `startRogueBattle` 重置已保存的战斗。
5. **归属跨战场稳定。** 用角色 `kit` 保存固定归属，每场战斗再映射单位 ID；角色永久死亡保留席位，武器人跟随主人。
6. **服务端也要锁座位。** 现有转发允许房主加四名玩家，尚无合作开局锁定。合作模式总人数最多四名，开局后只接受固定座位原凭据。`hotseat-game.js` 当前网络配置只接受跑团，也需支持合作和死亡后旁观。
7. **区分原房间重连与新房间恢复。** D3 房间 24 小时后会过期；仅保存旧房间地址和令牌不能实现新房码恢复原席位。D4 必须设计可由房主保存、在新房恢复且不泄露原始玩家令牌的身份延续方式，并测试过期/新房路径，不能只测试页面刷新。

## 适配方案建议（待实现）

- 在 `RunFlow` 增加房主内部的新局、执行、快照、恢复、开战和重绑战斗回调接口；保留现有单机入口。
- 独立的单局协调模块生成缓存的公开 `run` DTO 和带版本的操作目录；显示模块让房主与远端共用该目录。诊所改造使用输入参数加房主预览，不枚举全部方案，不向客户端传权威角色对象。
- `OnlineView` 显式投影单局进度、可见队伍、物资、当前任务/路线/服务、升级选项和建议；不广播原 `run`、原始日志或未来遭遇内部数据。
- 转发层可用 `mode: "coop"` 和仅房主可调用的原子 `sealSeats(expectedIds)` 实现锁座。锁定时核对完整席位集合并禁止解锁，恢复旧令牌仍可加入。
- 可由房主保存原玩家 ID 与令牌哈希，在新房预置固定席位，原玩家持自己的原令牌恢复；私有恢复数据不得进入显示 DTO 或调试导出。具体协议必须验证服务端明确支持模式与锁座，不能默默连接旧服务后误判已锁定。
- 一人一角色约束仅适用于初次开局；存活角色减少后仍能进入下一战，原席位继续旁观。

新增验证重点：锁座与加入竞争、离线席位不释放、错误令牌及昵称冒用、原令牌跨房恢复、房主战斗中刷新而不重开战斗、永久死亡后继续下一战、合作房主的隐藏信息过滤，以及 D3 原行为兼容。
