## 使用

1. 打开本地 `game.html`，转发服务填写 `https://backfire-relay.richardguu22.workers.dev`。这是已部署的独立测试服务；自行部署参照 [部署与费用](relay.md)。所有参与者填写同一服务地址，并使用相同游戏版本。
2. 主持人在 `game.html` 标题选择「联机开房」，填写昵称、选择一个跑团存档；空白槽会新建跑团，已有槽沿用原进度。
3. 玩家点「加入房间」，输入服务地址、六位房间码和昵称。昵称只是显示名；令牌才决定原座位身份，昵称相同不能冒充主持人或其他玩家。
4. 主持人在大厅分配角色，每名玩家最多一名英雄；未分配英雄及其武器人由主持人操作。点「开始跑团」后进入原探索界面，开战时沿用 D2 单位行动顺序和协助询问。
5. 主持人使用原探索、遭遇、战场、后台面板，以及「主持人工具」；玩家看到独立的公开战场。玩家选择行动、分步选项和目标，房主再次校验后结算。
6. 房间面板可发送主持人公告、指定玩家私信或玩家给主持人的回复。完整消息记录保存在主持人设备；实时画面保留最近一页，可点「查看更早消息」逐页回看。私信历史只发送给对应双方。
7. 断线自动重连。刷新后点「恢复上次房间」；房主恢复完整权威状态后才解除暂停。关闭网页不会迁移房主，恢复令牌和完整状态只在原浏览器里。

## 主持人工具与回合

- 默认由 AI 操作敌人；可为全部或指定敌人开启手动控制。敌方回合先运行 AI，再等待主持人操作手动敌人，最后点「结束敌人回合」。
- 手动技能和移动仍消耗原规则要求的点数，检查射程、目标、技能分步和失衡。手动敌人不提供自动意图预测。
- 「移出」不计击杀、不发奖励、不触发自爆；「直接击杀」经过正常死亡与奖励流程。配置物的「移除」与「摧毁」同理。
- 战斗中生成的敌人从下一次敌方阶段起行动：我方阶段生成可参加紧接的敌方阶段；敌方阶段中生成须等下一轮敌方阶段。
- 主持人工具提交的操作等待正在进行的演出完成。默认发送不含隐藏数据的摘要，「静默」仅不添加公开摘要，实际场面变化仍会同步。
- 原探索和后台面板继续可用；忙碌时的编辑在演出边界排队并重新检查状态。联机战斗中不能重置遭遇、切换存档或改变区数。静默勾选位于新增的主持人工具，原面板继续显示安全的通用摘要。
- 玩家在自己的顺位掉线，等待 60 秒后跳过；协助询问中的离线玩家按放弃处理。房主掉线全体暂停，不把主持权交给其他玩家。
- 顺序格按角色和已上场武器人分别计算，扣过点或已结束的格子锁定；一人可以操作多个单位，武器人动态加入/离开保留原 D2 规则。

## 保存与隐私边界

原跑团存档槽格式保持不变。`backfire-online-v1` 是房主独立的本机恢复数据，包含完整战斗、顺序锁定、主持人手动控制和消息；玩家只保存自己的连接凭据。不要分享浏览器存储里的重连令牌。

所有出站游戏消息统一通过 [白名单投影](privacy.md)：状态、结果、弹字快照、公开日志、重同步和私信历史均按收件人处理。远端渲染层不能将显示 DTO 传回规则状态，技能菜单也由房主生成。

房主恢复询问时，从保存的规则队列重建询问，用新编号拒绝旧回答，保留剩余倒计时和已经拒绝的操作者。尚未获同意的顺序互换作废，恢复后可重新申请。房主离线期间暂停倒计时。若浏览器存储空间不足，界面会提示保存失败，不能保证关闭页面后的恢复。
