# D3 收件人显示投影

`online-view.js` 是房主发送前的过滤边界。调用 `OnlineView.projectPacket(packet, { recipientId, gmId })`，身份来自房主绑定的连接，不能从消息自报的 `sender`、`role` 或 `gm` 推断。必须在每一个结果、确认、拒绝、重同步、加入恢复和消息历史发送路径调用。

主持人得到独立完整副本。玩家得到带 `displayOnly: true` 和 `schema: "backfire-online-display-v1"` 的白名单 DTO：它是不完整的显示数据，不是游戏状态，也不是规则执行上下文。远端界面只渲染 DTO 和提交房主提供的可用动作；不得执行原规则、技能可用性计算、存活判断、随机数或伤害预演。房主始终持有完整权威状态并完成校验与结算。

## 允许发送的内容

- 单位：身份、名称、阵营、区域、等级、当前经验、公开的各层 HP、ATK、DEF、AP、附赠行动、可见状态和明确登记的角色资源。各层统一为 `type/current/max`，兼容原演出快照的 `cur` 输入。武器归属保留。
- 战场：区数、当前回合/阶段、天气、风向、相位、是否锁定、白名单场地、间隔和配置物。远端有天气图标与配色，并显示风向、相位和锁定标记。
- 战场画面标签（issue #229，只是画面、不参与结算）：`region` 这场战斗所在的区域，只放行房主配置表认得的区域名（`world-data.js · battleRegionName`，地图地点 id 换成区域名；房主没有配置表时一律不发）；`light` 光影，只放行 `day` / `dusk` / `night`。主持人选的、从地图来的（`regionPick` / `lightPick` / `regionMap`）是房主自己的，不发。
- 公共物资：奎支、背包水量及道具 `id/name/qty`；名称由房主物品目录提供，道具描述、恢复数值和未知属性不发送。远端探索显示物资与每名角色当前经验。
- 会话：操作者姓名/在线状态、顺序、确认、交换和等待信息。询问选项再次按单位所属操作者筛选，避免把别人的缓存视图发错人。
- 联机进度：主持人手动控制阶段、网络模式，以及离线单位的公开身份和等待截止时间；不传播断线凭证或后台元数据。
- 动作菜单：`projectActionMenu()` 只保留选项展示及已登记的 JSON 选择字段。完整动作只允许 `skill/move/standUp/useItem/endTurn` 及 `actor/skill/target/picks/dest/item`；未知字段或嵌套状态使该动作被剔除。目标、射程与费用仍由房主判断。
- 角色资料 / 武器页 / 背包明细（玩家点「角色资料」「武器」「背包」时请求，`type: "sheetData"`）：`SkillText.sheetData()` 与 `armoryData()` 的规则说明和公开数值，经 `projectSheets()` 递归去掉 `shp/shpMax` 等坚毅生命字段；背包给 `id/name/qty` 和道具说明；道具说明是固定的目录文字，提到坚毅生命（如「失去 6 坚毅生命」）也照常显示，不做敏感词过滤，只去掉控制字符。玩家看不到的是自己角色的坚毅生命数值。这些是玩家本来就该知道的自己角色与队伍物资信息，作者在实机测试后要求开放。
- 检定、属性点申请（`view.checks`、`view.attrRequests`）：检定的熟练项、难度、说明、每名角色的成功率与优劣势、掷出的点数和成败；属性点申请的角色、属性和状态。都是公开的规则信息。按钮掷骰的结果（点数、档次）写进小队频道；主持人暗骰（`chat` 中 `secret` 的行）不发给玩家。
- 大字（`view.title`）：主持人公开广播的大字、小字、风格、停留秒数，本来就是给所有玩家看的。
- 战绩（`sheetData.battles`）：最近 10 场的结果、回合、评价、掉落和每人的战场数据（伤害、击破、承伤等公开统计），不含坚毅生命。战斗结算（`result.drops`）带掉落的奎支与物品名、数量。
- 特殊棋盘（`state.board`）：区号、坐标和连接；场地与间隙按棋盘上实际的区和连接发送。
- 小队聊天：大厅、探索、战斗全程开放，房主保留最近 300 条，按 `{id, operatorId, name, text, at}` 投影。正文（`chatText()`）保留换行和全角字符（字符画靠全角空格对齐），其余控制字符、零宽和双向控制字符照样去掉；敏感词按 NFKC 规范化后的文字判断，命中的整条不发。
- 结果：固定公开标志、胜败/撤退和 D/C/B/A/S 评级摘要；结束画面显示实际评价、分数和经验倍率。原始返回值、`notes`、存档、单位副本及任意嵌套结果不传播。

坚毅生命数值、最大值、基础值、相关内部标记、承伤统计、后台备注、存档、撤销历史、规则队列、未来敌人决策和未知资源均不发送。新增字段默认私有，需要先登记具体的显示语义并补测试。

## 演出和文字

原 `tape.pop.snap` 逐个单位重新投影。受击者正在使用隐藏生命、濒死、死亡，或无法确认公开 HP 来源时，伤害/治疗数字不下发。姿态伤害等公开效果仍可显示。原始弹字只允许固定公开词表，未知事件不透传。

不能把原 `state.logPages`、`tape.log`、`status/res`、`notes` 或异常消息直接当玩家记录。公开记录使用新语义事件：

```js
{ kind: "action", actorName: "瑞比", actionName: "普通攻击", seq: 1 }
{ kind: "phase", phase: "player", turn: 2, seq: 2 }
{ kind: "gm", summary: "主持人更新了天气", seq: 3 }
{ kind: "gm", action: "spawn", unitName: "狂徒", zone: 2, level: 3, seq: 4 }
{ kind: "gm", action: "remove", unitName: "狂徒", seq: 5 }
```

`projectLogs()` 使用固定模板，不接受任意 `text` 或 `public: true`。`remove/kill`、`propRemove/propDestroy` 与 `manualOn/manualOff` 分别给出移出与击杀、移除与摧毁、开启与关闭手动控制的公开说明。GM 备注默认退为通用调整提示；静默事件丢弃。操作错误映射为固定公开原因，不回传底层异常的任意细节。`systemNotice` 只允许固定提示“房主遇到处理错误，请等待主持人确认后继续”，不接受其他错误文本。

公开标签和有明确收件人的人工消息是显式展示入口，仍对坚毅/后台等敏感标记做保守过滤。该词检不是任意自然语言的保密证明；关键保护来自不允许原始日志、未知属性或后台对象进入这些入口。渲染端使用文本节点或 HTML 转义，不能把消息、名称或标签当 HTML 执行。

## 私信和重连

消息白名单为 `{ id, from, to, text, at, private }`。玩家只收到主持人发给 `all` 或自己的消息，以及自己发给主持人的回复；其他人的私信及回复全部移除。完整房间消息保存在主持人设备并随房间检查点恢复。实时与重同步包先按收件人过滤，再带最近 300 条符合条件的消息；较早记录通过 `messageHistory({beforeId})` 每页最多 100 条读取。房主按可信连接身份筛选后定位游标与分页，返回消息继续经过同一投影，不显示全局消息条数或他人私聊数量。界面按 ID 合并去重，读取旧页不弹新消息提示；换房间或重同步会取消旧请求，重同步从新窗口重新分页，避免长时间掉线后两个历史片段之间漏页。消息栏说明“消息保存在主持人设备；私信仅双方可见”。消息上的任意嵌套历史/元数据不传播，不能发送原始房间保存对象。

## 显示数据的传输差异编码

`online-wire.js` 必须在房主完成 `OnlineView.projectPacket()` **之后**调用。每名收件人有独立编码缓存，客户端有独立解码缓存。普通结果只发送消息和公开记录的新条目，并带窗口长度；首包、替换窗口或重同步发送完整实时窗口；较早历史页独立投影发送，不进入规则队列。演出每包的第一份单位快照为全量，后续快照可用改变的字段、字段删除、离场单位和顺序差异表示；整份快照更小时保留整份。快照差异不依赖上一包，因此重同步不需要补播旧演出。跑团长休结算（`rest`）整份没变时不重发，只带 `restUnchanged`，客户端用上一次收到的那份还原（`null` 照发）；重同步一律整份发送。

客户端先验证序号、拒绝重复和缺号，再调用 `unpack()`，之后才交给显示回调。解码只恢复脱敏 DTO 的数组和字段，不运行技能、伤害预演、随机数或其他规则；解码后的各帧也不共享可变引用。编码包不能重新经过隐私投影，否则传输元数据会被白名单移除。未知格式、缺少基线或非法差异会拒绝解码，且不会修改上一份有效缓存。

重同步会使旧演出任务失效，显示层同时丢弃旧动作菜单。协调层在每个异步显示回调前后检查任务是否仍有效；显示失败时等待新的全量重同步，不继续播放已排队的后续结果。旧任务晚到的异常不会覆盖新恢复的画面或错误提示。断线或暂停时结束未完成的 RPC 等待，不自动重发可能已经结算的动作。

投影不保存共享引用、不修改权威状态、不调用规则或随机函数。`tests/online-view.test.js` 覆盖完整数据面、嵌套与未来字段、隐藏生命弹字、私信错收件人、Unicode 敏感文本、动作菜单及真实战斗状态的无副作用投影。发送路径接入和多页面验证由联机集成测试覆盖。

`online-actions.js` 只在房主运行，菜单计算放在隔离 `state/LEDGER` 的 `inspect` 中，复用原技能分步和目标预演，但只返回安全选项与待提交指令。预演不进入指令记录；技能提交时仍需重新校验。`tests/online-actions.test.js` 验证真实规则下的选项、无权请求与失败恢复，并断言状态原引用、耐久、随机数、指令记录和顺序账本不变。

`online-ui.js` 只接收 `OnlineGame` 的显示 API。玩家战场独立渲染公开 HP、行动点、场地与弹字，按顺序等待演出结束；它不把快照灌入原游戏。`tests/online-ui.test.js` 在浏览器中让规则入口的读取直接抛错，仍能完成菜单、消息和演出交互，并覆盖 390px 宽度、演出中重同步和旧菜单晚到。`tests/online-wire.test.js` 验证差异往返、独立收件人缓存、错误不污染基线和体积减少；`tests/online-coordinator.test.js` 用真实协调层验证序号检查、异步任务失效与断线 RPC 清理。
