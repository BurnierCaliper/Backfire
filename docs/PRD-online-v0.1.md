## 1. 目标与范围

| | 内容 |
| --- | --- |
| 要做 | ① **在线合作单局**：2–4 名玩家各控一名角色，一起打 Roguelike 单局（现有「新的一局」流程）。② **在线跑团**：主持人开房，玩家用自己的设备看战场、操作自己的角色；主持人保留后台和遭遇配置。 |
| 不做 | 单人模式联机；对战（PvP）；排行榜 / 种子挑战；观战；账号系统；付费服务；语音。 |

## 2. 已定规则（作者确定，不可更改）

1. **每人只控制自己的角色**：一名玩家只能操作自己选的那一名角色，以及这名角色自己的武器人（例如绯秋的两把刀、夕夏的柏妮尔）。别人的角色和武器人只能看，不能点。
2. **轮流行动**：只有轮到自己时，才能使用自己角色（和自己武器人）的**行动点和附赠行动**。轮到别人时，自己的技能按钮全部不可用。
3. **每个我方回合开始时选行动顺序**：
   - 弹出「行动顺序」画面，格子数 = 玩家人数（2 人 2 格、3 人 3 格、4 人 4 格，按实际人数增减）。
   - 每名玩家点一个格子，格子上出现他的角色名字；所有玩家实时看到谁占了哪一格。这就是本回合的行动顺序。
   - 玩家可以先协商：全员确定前可以改选格子；全员选完后按格子顺序依次行动，轮到的人点「结束」交给下一格。
   - 敌人回合照旧，不受影响。
4. **协助格挡、协助攻击在触发时询问协助者本人**：
   - 敌人攻击我方、出现可以协助格挡的人时，只把询问发给**能格挡的那几名玩家**，由他们自己决定格不格挡。
   - 我方打出失衡、可以协助攻击时，同样只问能协助攻击的玩家。
   - 不在自己回合也会被问到（协助本来就发生在别人行动时）；其他玩家看到「正在等待某某回应」。
5. **联机没有撤销**：联机时隐藏「撤销」，相关快捷键无效。

## 4. 总体方案

### 4.1 房主说了算（host-authoritative）

- 开房的人（合作模式是任意一名玩家，跑团模式是主持人）的浏览器持有唯一一份权威 `state` / `run`，负责全部规则结算和存档。
- 其他玩家只发**指令**，收**结果**：`{ seq, state, tape, view }`。客户端用收到的 `state` 替换本地 `state`，再用现有的 `playTape` 播放演出。
- 客户端不运行规则结算（预览除外：伤害预览可以在客户端对本地副本算，结果只用于显示，不回传）。
- 不做「各算各的、只同步指令」：规则里随机数太多，迟早不同步。

### 4.2 通信层

- 抽象一个 `Transport` 接口：`send(msg)`、`onMessage(fn)`、`close()`，至少两个实现：
  - `LocalTransport`：同一页面内存转发，用于热座（D2）和自动测试；
  - `RelayTransport`：经过消息转发服务，用于 D3 / D4。
- 转发服务只转发消息、按房间分组，不跑游戏规则。游戏网页仍然是纯静态文件（可放 GitHub Pages）。具体用哪个服务见第 8 节。
- 所有消息带 `protocol`（协议版本）和 `build`（游戏版本标识，例如源码哈希）。不一致的客户端拒绝加入，并提示「版本不同，请刷新」。

### 4.3 消息草案（实现时可调整字段名，语义不变）

| 方向 | 类型 | 内容 |
| --- | --- | --- |
| 客户端 → 房主 | `join` | 房间码、昵称、重连令牌（有的话） |
| 房主 → 全体 | `lobby` | 座位表（玩家 id、昵称、是否在线、选了哪个角色）、模式（合作 / 跑团） |
| 客户端 → 房主 | `pickHero` | 选角（合作模式；跑团模式由主持人分配） |
| 客户端 → 房主 | `cmd` | 一条指令（见 4.4），带客户端自增编号 |
| 房主 → 发送者 | `reject` | 指令被拒绝的原因（不是你的角色 / 不是你的回合 / 规则不允许……） |
| 房主 → 全体 | `result` | `seq`（房主自增）、tape、结算后的状态（按收件人过滤，见 4.5） |
| 房主 → 指定玩家 | `ask` | 询问：协助格挡 / 协助攻击 / 其他需要本人回答的选择；带选项、截止时间 |
| 客户端 → 房主 | `answer` | 对 `ask` 的回答 |
| 房主 → 全体 | `waiting` | 「正在等待某某回应」 |
| 房主 → 全体 | `order` | 行动顺序格子当前状态（谁占了哪格、谁已确定） |
| 客户端 → 房主 | `orderPick` / `orderConfirm` | 选格子 / 确定 |
| 房主 → 全体 | `chat` | （可选）协商用的文字消息，见第 8 节 |

客户端发现 `seq` 跳号时，向房主请求一次完整状态（`resync`），不自己猜。

### 4.4 指令（D1 的核心）

一条指令是一个只含数据的对象，例如：

```js
{ type: "skill", actor: "<单位 id>", skill: "berniel_spit", picks: { dest: 2 }, target: "<单位 id 或 prop:xxx 或 gap:1-2>" }
{ type: "endTurn" }            // 联机里是「结束我的顺位」
{ type: "standUp", actor }     // 起身
{ type: "useItem", actor, item, target }
{ type: "retreat" }
{ type: "run", action: "chooseNode", index: 1 }   // 单局决策
```

- 现在所有会改变战斗或单局状态的界面操作，都改成「生成指令 → `dispatch(cmd)`」。单机时 `dispatch` 直接本地执行，行为和现在完全一样；联机时客户端把指令发给房主。
- 房主执行前先**校验**：发令者是否拥有 `actor`；是否轮到他；技能是否可用（复用现有的 `skillRequirementError` / `skillTargetError`）。不合法就回 `reject`，不改状态。
- 指令和结果都写进指令日志，方便排查不同步。不承诺日志能确定性重放（因为随机数），但要能人工复查。

### 4.5 按收件人过滤

- 跑团联机：发给玩家的状态里删除坚毅生命数值等主持人专用信息；后台数据不下发给玩家。
- 合作联机：所有人看到的信息一致（坚毅生命按现有 `GAME_MODE` 规则对所有玩家隐藏）。
- 过滤在房主发送前完成，测试要断言玩家收到的数据里确实没有这些字段。

## 5. 分期需求与验收

每一期单独开 PR，合并后再开下一期。每期都要：README「规则改动记录」最上面加一条、补测试、`npm test` 和 `npm run test:ui` 全部通过。

### D1 · 统一操作指令（不联网）

1. 实现 `dispatch(cmd)` 和指令表，覆盖战斗内全部玩家操作：技能（含分步选择）、移动、起身、使用道具、开始战斗 / 结束回合、撤退、开战前的选择（`askOpeningChoices`）、格挡 / 协助的回答。
2. 覆盖单局内全部决策：接任务、选路线节点、休息 / 守夜、商店买卖、工匠、诊所、检定、升级选择、离开节点。
3. 单机所有入口改走 `dispatch`，行为与现在逐项一致：现有测试不改断言就能通过；新增测试把同一场战斗分别用「旧调用方式」和「指令」各打一遍（固定种子），结果一致。
4. 指令全部可 `JSON.stringify` / `parse` 往返；新增一个「把指令日志存成文件」的调试入口。

验收：单机玩法零差异；全部玩家操作都有对应指令且有测试；指令能序列化。

### D2 · 角色归属、行动顺序、询问协助者（热座，不联网）

1. **归属**：每名英雄记录所属玩家 `owner`；武器人跟随主人（`weaponOf`）。伙伴支援、召唤物等不属于任何玩家的单位不能被玩家直接操作。
2. **行动顺序画面**（第 2 节第 3 条）：
   - 每个我方回合开始、回合开始效果结算之后弹出；格子数 = 当前玩家人数。
   - 点格子 → 格子显示角色名字；可以改选；每人点「确定」；全员确定后开始。
   - 同一格只能有一人（冲突规则见第 8 节）。
   - 已经阵亡 / 永久死亡的玩家的处理见第 8 节；倒地但还能起身的玩家照常占格子（起身本身用他的行动）。
3. **轮流行动**：只有当前顺位的玩家能用自己角色和武器人的行动点、附赠行动；顺位玩家点「结束」后交给下一格；最后一格结束后进入敌人回合。界面上明确显示「现在轮到谁」和顺序条。
4. **询问协助者**：`resolveQueues` 里的协助格挡、协助攻击询问，只交给能协助的单位的所属玩家回答；多名玩家都能协助时同时询问，**先回答「我来」的那位生效**，其他人的询问关闭（如何处理同时到达见第 8 节）；全员都选「不」或超时才算不协助。其他人看到「正在等待某某回应」。
5. **隐藏撤销**：多人模式（包括热座）不存撤销快照，按钮和快捷键都不可用。
6. **热座模式**：一台电脑上模拟多名玩家（顶部切换「当前操作的玩家」），用 `LocalTransport` 走完整的指令 → 房主 → 结果流程。它主要是开发和测试工具，可以先不对普通玩家开放（入口放在开发菜单或 URL 参数）。

验收：热座 2–4 人能完整打一场战斗；自动测试证明：不是自己的角色、不是自己的顺位时指令被拒绝；协助询问只发给对应玩家；单机模式不出现顺序画面、行为不变。

### D3 · 在线合作单局

1. **开房 / 加入**：标题界面加「联机」入口 →「开房」生成 4–6 位房间码 /「加入」输入房间码和昵称。大厅显示座位、在线状态、所选角色；房主点「开始」。
2. **选角**：2–4 人，每人选一名角色（不能重复）；队伍人数 = 玩家人数；之后走现有新局流程（物资、任务板等按人数）。
3. **同步**：房主执行指令后广播 `result`；客户端播放演出。演出期间收到的新结果排队，不能跳过或错序。
4. **单局决策**：按第 8 节定下的规则（建议默认：房主决定，其他人可以投票提示）。商店、工匠、诊所等花全队资源的操作，所有人都能看到结果和余额。
5. **存档**：只存在房主机器上，用现有 `SaveStore`，加一个「联机局」标记；房主下次开房可以选择继续这个局，玩家重新加入后按昵称 / 令牌回到原座位。
6. **掉线与重连**：按第 8 节的规则；重连后客户端拿到完整状态，回到正确的画面（战斗中 / 任务板 / 询问中）。
7. **转发服务**：按第 8 节选定的服务实现 `RelayTransport`；README 写清楚部署步骤、所需账号、费用（免费额度）和配置项。游戏本身不新增运行时依赖（客户端连接代码可以内联，或从允许的 CDN 加载并有离线降级：联机不可用时单机照常）。

验收：两台不同的机器 + 一台手机（390px 宽）通过房间码完成第 1 幕；断网 30 秒再连上能回到原位置继续；房主刷新页面后能从存档继续并让大家重新加入；全程任何客户端不能操作别人的角色。

### D4 · 在线跑团

1. 主持人 = 房主。主持人开房时选择一个跑团存档空位；玩家加入后由主持人把角色分配给玩家（也可以主持人自己控制没分配的角色）。
2. 主持人保留：后台面板、遭遇配置、天气 / 场地设置、探索环节的买卖 / 休息 / 升级操作；这些界面只在主持人那里出现。玩家只能在战斗中操作自己的角色、回答协助询问。
3. 信息隐藏：发给玩家的数据里去掉坚毅生命数值和后台数据（第 4.5 节），有测试断言。
4. 战斗规则与合作模式相同（行动顺序、轮流、询问协助者、无撤销）。

验收：主持人带两名玩家完成一场遭遇；玩家端抓包 / 测试中看不到坚毅生命和后台数据；主持人能在战斗中途用后台改数值，玩家端正确同步。

## 6. 非功能要求

- **性能**：每次行动消息 ≤ 50 KB（当前一场 4v3 状态约 13 KB）；回合制，正常网络下操作到全员看到结果 < 1 秒（不含演出时长）。
- **健壮**：任何客户端发来的非法消息都不能让房主崩溃或改坏状态；房主出错时记录日志并通知全体，而不是卡住不动。
- **安全**：合作游戏不防作弊到服务端级别，但房主必须校验归属和顺位（第 4.4 节）。房间码不可猜测性足够即可；不收集个人信息。
- **兼容**：Chrome / Edge 桌面版、Android Chrome、iOS Safari（真机验证一次）。
- **测试**：
  - 用 `LocalTransport` 在 Node 里起一个房主 + 多个客户端，跑完整战斗，断言各客户端状态与房主一致；
  - Playwright 开两个页面互相联机（可以用本地转发服务或模拟转发）；
  - 所有新测试纳入 `npm test`，需要浏览器的纳入 `npm run test:ui`。

| Q2 | 有人掉线怎么办？ | 他的顺位到了时等 60 秒，期间显示「某某掉线」；仍未回来则自动跳过他这一顺位（不由 AI 代打）；协助询问视为「不协助」。重连后从下一次轮到他开始照常操作。 | |
| Q3 | 协助询问多久不回应算放弃？ | 20 秒，倒计时对所有人可见。 | |
| Q4 | 多人同时可以协助时谁生效？ | 先点「我来」的生效（以房主收到的先后为准），其他人的询问自动关闭。 | |
| Q5 | 两人同时点同一个顺序格子？ | 先到者占格；后到者提示「已被占用」。全员确定前可以改选或互换。 | |
| Q6 | 选顺序要不要限时？ | 不限时；但房主可以点「按当前格子开始」，没选的人自动排到剩下的格子。 | |
| Q7 | 协商行动顺序用什么？ | 顺序画面里加一个简单的文字聊天框（只在大厅和顺序画面显示）；语音交给玩家自己的工具。 | |
| Q8 | 角色倒地无法起身 / 永久死亡后，这名玩家做什么？ | 本场剩余时间不占顺序格子，只能看；永久死亡后本局剩余时间旁观（以后可以考虑接手新角色，本期不做）。 | |
| Q9 | 房主掉线？ | 房主是唯一权威，房主掉线时全体暂停并提示；房主回来后从存档继续。本期不做房主迁移。 | |
| Q10 | 转发服务用什么？ | Cloudflare Workers + Durable Objects（免费额度够小规模使用、稳定）；备选 PartyKit 或 Supabase Realtime。WebRTC 直连在部分网络下连不上，不作为首选。 | |
| Q11 | 联机局人数下限？ | 2 人起（1 人请用单人模式）。 | |
| Q12 | 联机局能不能中途加人 / 换人？ | 本期不能：开局后座位固定，只能原座位重连。 | |
