# HD-2D 战场原型（第一阶段 + 第二阶段 · 一、二）

「八方旅人」那种 HD-2D 的方向：2D 角色站在 3D 小场景里，加景深、光影、粒子。角色暂时没有立绘，**用铭牌代替角色**。
这是一个独立的原型页面，规则用的是真规则（`BattleSim.setup`）。
画面只用**联机玩家拿得到的数据**：房主的完整战斗状态先过一遍 `online-view.js` 的白名单（`OnlineView.projectState`），再交给布局和场景（见下面「第二阶段 · 一」）。

**#261 起开始接进正式游戏**：战场的模块（布局、镜头、场景、地台、远景、场景美术、天气、界面数据、攻击演出）挪到了仓库根目录的正式目录 `hd2d/`，这个原型页改成引用那里（`../../hd2d/…`），不复制两份；正式战斗画面（game.html）顶栏的「新画面（HD-2D）」开关也用同一份。见下面「接进正式战斗画面（issue #261）」。

## 怎么打开

three.js 用 ES 模块，浏览器不让 `file://` 直接加载模块，所以要起一个本地静态服务（在仓库根目录）：

```
python3 -m http.server 8000
# 然后打开 http://localhost:8000/prototypes/hd2d/index.html
```

- 切换演示战场：右上角下拉框，或者网址后面加 `?demo=mine` / `?demo=desert` / `?demo=cross`
- 切换区域（默认地台的地面、远景、灯跟着变）：右上角第二个下拉框，或者网址后面加 `?region=沙漠`（区域名，或者地图地点 id，如 `?region=mine_3`；写一个认不得的名字，如 `?region=?`，看兜底的样子）。三个演示默认分别在第一采矿场、沙漠、外城区；切换时网址跟着改，复制网址就能回到同一个画面，例如 `?demo=cross&region=巨人城`
- **三段镜头**：顶栏的「镜头 远 / 中 / 近」三个按钮、键盘 `1` / `2` / `3`、滚轮（往前滚拉近、往后滚拉远，一次滚动跳一段）。点一个区的地台或者区里的铭牌就选中这个区（地台顶面亮一圈细框，顶栏写着「3 区 · 高压」），中景 / 近景看的就是它；中景 / 近景里左右键或者屏幕两边的箭头换到相邻的区。网址跟着记 `?cam=near&zone=3`，截图时复制网址就能回到同一个镜头，例如 `?demo=cross&cam=near&zone=3`
- 鼠标：左键拖动小幅转动、右键拖动平移（角度、平移范围都有限制，每一段的俯角范围不同）；鼠标停在铭牌上高亮并展开详细（等级、ATK、血量数字、状态），点一下选中（只是画面，不接规则），点空地取消
- **特写**（#237）：近景里双击一个单位（铭牌，或者地台上它脚下的站位），镜头推到它面前特写，它的铭牌再放大一点（别的铭牌变淡，压到它的藏起来）；滚轮往后、按 `2` / `1`、点「远 / 中」就退出特写（往后滚一下回到正常的近景，按 `3` / 点「近」也是）；左右换区、点别的区也退出。控制台里 `HD2D.sc.closeUp(单位 id)` 也行
- 手机：单指转动，双指平移（不缩放，用顶栏的远 / 中 / 近）；窗口比较窄（竖屏）时战场整块转 90°，直排沿前后排开，铭牌才看得清
- 面板：底部「技能」栏、左边「队伍」栏、右边「日志」抽屉都能收起（手机默认全收起，只露一条 / 一个按钮）；点队伍栏里的人可以换当前行动单位
- **演示出招**（#230）：技能栏右上角「原型」那一小块里的「演示出招」按钮（控制台里 `HD2D.strike()` 也行）。房主用规则结算一次当前行动的人的普通攻击（够不着就换我方别人；连按会轮流换目标），投影成联机玩家收到的包，画面只按这个包播攻击演出和伤害数字。见下面「第二阶段 · 二」
- 技能栏照正式战斗画面的样子（#238）：左边普通技能按钮（左上角属性、右上角攻击 / 技能），右边「唤出武器人」和「结束回合」两个大按钮；技能按钮、这两个大按钮现在都还是摆设（点了只弹提示）。见下面「#238」
- **换天气看效果**（#240，截图用）：网址后面加 `?weather=sand`（`snow` / `acid` / `thunder` / `heat` / `glow` / `phase` / `none`）；沙暴再加 `&wind=W` 换风向（`12` / `21` / `E` / `W` / `S` / `N`，要是这块棋盘能用的），相位加 `&phase=2` 换阶段（0–3）。和主持人改天气一样写进战斗状态，画面照样只读投影。例如 `?demo=cross&weather=sand&wind=S`（夜晚的沙暴，风朝镜头吹）
- 需要能用 WebGL 的浏览器

- 铭牌（紧凑版）：名字一行；状态小圆点 + 分层血条 + 架势菱形一行；右上角贴着一小块行动点 / 附赠（#238）；等级、ATK、血量数字、架势、行动点 / 附赠、状态文字悬停 / 选中时从头顶展开。我方绿边、敌方红边；脚下有接触阴影；飞行单位浮起来，下潜单位半透明、下半截蒙一层沙色

## 第二阶段 · 二（issue #230）：演示出招——攻击演出 + 伤害数字

方向照主人说的：**不做 3D 特效模型，用正式游戏现成的 2D 演出**（attack-fx.js 的贴纸风刀光 / 冲击星 / 弹道、hit-fx.js 的受击粒子），画在 3D 沙盘上面那层全屏画布上，位置跟着铭牌走。只改了 `prototypes/hd2d/` 和测试；attack-fx.js / hit-fx.js 原样加载，**一行没改**（没加参数）。

这一步做了：

1. **适配器**（`hd2d-fx.js`，纯函数）：attack-fx / hit-fx 要的是「单位在屏幕上的矩形」，正式游戏里是单位卡的 DOM 矩形（game.js / online-ui.js 的 `rectOf`）。这里换成按**这一刻的镜头**把 3D 铭牌投影到屏幕上（和布局 / 场景同一个公式 `L.plateRect`：按远近缩放、后排抬高、近景放大的那张按放大的尺寸），区 → 地台顶面四个角投影后的外框。场景给三个接口：`sc.lensNow()`（镜头位置、看的点、视野、画面大小）、`sc.plateOf(id)`（铭牌现在在哪、抬多高、是不是放大的）、`sc.zoneOf(id)`；适配器每次被问都重新投影，所以远 / 中 / 近切换、过渡、玩家拖动转过去，矩形都跟着变。矩形两种写法都给：attack-fx 要的中心 + 宽高（`{ x, y, w, h }`，y 在卡片高 42% 处，和 game.js / online-ui.js 一样）、HitFx.burst 要的 `left / top / width / height`。`track(id)` 给 attack-fx 的击倒红叉（它本来就有 `track` 参数：镜头动了红叉跟着铭牌走）；被打倒、从画面上拿掉的单位留在最后看到的地方
2. **演示出招**：技能栏右边一个按钮。
   - 房主那边（`hd2d-host.js · strike`）：先开战（和 `BattleSim.run` 一样），挑当前行动的人的普通攻击（够不着就换我方别人；下潜中 / 躲藏中的敌人规则不让选，不挑；连按轮流换目标；演示用：行动点不够就补上，只为了能反复按），`runSkill` 真的结算一次（再 `BattleSim.resolveQueues` 把协助格挡这些排队的处理完）。结算时规则弹的字（`spawnPopup`）照 game.js 记成演出带（`type: "pop"`，带那一刻的单位 `snap`），攻击演出照 game.js · `strikePlan` 挑（`AttackFx.resolve`：属性、隔几个区、几段），公开日志写「谁 · 用了什么」，拼成联机的结果包，过 `OnlineView.projectPacket`（收件人是普通玩家）= **联机玩家收到的那一份**
   - 画面这边（`hd2d-play.js · play`）：**只拿这个包**。`HD2DFx.cues(packet)` 排演出：谁打谁、招式、每一段主攻击打中谁、要弹的数字（只用包里投影过的 `value`）、谁被击倒（出招前站着、包里倒下了）、有没有格挡。然后 attack-fx 的 `windup`（出手）→ `travel`（弹道，范围招式画 `area`）→ 第一下打中的那一刻**铭牌换成包里的 state**（血条跟着掉，`pv = packet.state`，不再从房主的 st 投影）→ 每一段 `impact`（刀光 / 冲击星，多段左右交替）+ `HitFx.burst`（受击粒子）+ 这一段的数字，段与段之间隔 `FX.timing.hitGap`（走 `AttackFx.after`，跟着演出倍率）→ 格挡 `clash` → 击倒 `ko`（红叉跟着铭牌）
3. **纸片风伤害数字**（DOM，`#hd2d-pop` 一层，盖在受击粒子上面）：粗墨线描边 + 属性色 + 往下错开的墨色投影，像一张贴纸拍上去（歪一点、弹一下、停住、往上飘一点淡掉）。普通伤害按属性色；**大伤害**（规则的 `bigHitInfo(等级, 伤害)`，和房主 `spawnPopup` 判「大伤害」同一个公式，只用投影里的等级和伤害）数字后面加 `!!`、放大、垫一张米白贴纸底；**击破**是黑底胶带标签「击破 N」；**格挡**是全息青的「格挡」（包里 `fx.parried`）；治疗薄荷绿 `+N`；状态字（白名单里的弹字：灼烧、无效……）小一号。字号按铭牌在屏幕上的宽缩放（**近景放大的铭牌上数字大，远景小**）；几个数字同时出来时先在铭牌头顶左右错开，压到了就往上叠，顶到顶栏换旁边一列，**两两不压住**（连往上飘的那一截一起算）；铭牌不在画面里（近景看的是别的区）就不弹。系统开了「减少动态效果」时数字不弹不飘（attack-fx 自己也只留很短的一闪）
4. **坚毅生命绝不显示**：包是投影过的（`projectState` 没有 shp；`projectTape` 遇到打在坚毅生命上的、濒死的单位干脆不给数），数字只认包里的 `value`，打在坚毅生命上的那一下只演打中、不弹数字

### 一、沙暴（先做）

查下来以前沙暴不明显有三个原因：① 远景（天幕、天边画的远景、中景剪影）的材质都不吃场景雾（`fog: false`），沙暴时远景和晴天一模一样；② 沙暴的雾是 `near 0.55 / far 2.3`——起雾早但拉得很长，战场上只蒙 5%，**战场后面的地反而比晴天还清楚**（后沿外 10 格：晴天 31%，沙暴 13%）；③ 3D 沙粒一直往 +x 飞，不看风向。

1. **2D 沙雾**（`hd2d-wfx.js`）：沙暴时 `WeatherFx.sync` 在 2D 层里放正式画面的 `.wfx.wfx-sand`：一阵一阵顺着风向卷过整个画面的沙雾（两层不同速度，最浓约 0.5–0.7，中间有一段平静）+ 一层很淡的沙色底。傍晚 / 夜晚用正式画面的夜晚样子（`.g-app.is-night .wfx-sand`：更暗更淡；和正式画面一样，规则上的夜晚 = 傍晚 + 夜晚）。2D 层只带 `g-app` / `is-night` 两个 class、不写 `data-weather`，所以 `weather-fx.css` 里给正式画面面板换色的规则一条都套不上来
2. **风向一致**：规则的 `state.sandDir` 是棋盘上的方向（`engine.js · SAND_WIND_VEC`，联机白名单里有），`windOf` 照布局的坐标换成 3D 世界里的风（竖屏时棋盘整块转了 90°，风跟着转），`screenDir` 再看它在屏幕上往哪边吹，写进 2D 层的 `data-sand-dir`。3D 的沙粒、拖影、大团沙尘也顺着这个风飞（`sc.setWind`）。测试核对过：各种棋盘、每个能用的风向、横竖屏，风都是从规则上「顺风」的区吹向「逆风」的区，2D 沙雾在屏幕上也往这边卷
3. **3D 的雾更浓更黄**（`hd2d-weather.js` 的 `WEATHER.sand`）：雾色按光影分开写、更偏沙黄（`fog`），场景的雾色往它靠 0.8（`mix`，以前所有天气都是 0.6）；起雾 / 全进雾都更近（`near 0.76 / far 0.9`）。三个演示 × 远 / 中 / 近：战场后沿外 10 格进雾 60–91%（以前 11–13%），近景看的那个区几乎不进雾、中景只蒙一层薄雾（≤ 15%），远景最远的那排区 ≤ 40%，铭牌（DOM）不受雾影响。雾距 / 雾色的算法搬成纯函数（`fogRange` / `fogColor`），场景和测试用同一个
4. **远景蒙上沙色**（`hd2d-backdrop.js` 的 `colors.dust`）：天幕的四个颜色往这时的雾色靠一半（`sky`），贴地融进雾里的那一截从 0.16 加高到 0.42（`haze`），中景剪影至少往雾色靠 0.35（`veil`），星星、亮云看不见，太阳的光晕只剩六成（`sun`）；转到天幕外面露出来的屏幕背景也一样（`dustSky`）。雷鸣的风暴天空优先（两个不会同时出现）
5. **远处景深更糊**：远处的糊上限再乘 1.8（`dof`），远景剪影只剩轮廓
6. **沙粒横飞**：1100 → 1600 颗、大一点、快一点，再加一层 520 条顺着风的短拖影（`streak`，lines），看得出在横飞；大团沙尘 120 → 160 团
7. **三段镜头**（`WFX.tier`）：远景 2D 层的不透明度 0.85；中景 0.92、放大 1.06；近景 1（正式画面原样的强度）、放大 1.14；特写 1、放大 1.22——越近沙雾一团团越大、越浓，像身处其中。换段时跟着镜头一起渐变 0.5 秒（`fade`）
8. **减少动态效果**：照 `weather-fx.css` 现有的处理（沙雾停住、只留 0.15 的一层）；3D 的沙粒本来就停住；换段时 2D 层不渐变
9. **层级**：`#stage`（z 0）里 3D 画布（不定位）< 2D 天气层（z `WFX.z` = 0）< 铭牌层（z 1）；纸片影子、界面面板、攻击演出、伤害数字都在 `#stage` 外面、更上面；2D 层不挡鼠标。想让沙雾连铭牌一起盖住（像正式画面的单位卡）就把 `WFX.z` 改成 2

   - `spot()`：酸雨的涟漪落在哪（返回叠加层里的百分比 `{ x, y }`，返回 `null` 这一下不落）
2. **雷鸣不打架**：3D 打雷闪白的那一下，2D 层跟着淡掉（`WFX.weather.thunder.flash` × 场景这一帧的闪光 `sc.flash`；不然暗色的云影会把闪白压暗一块），雷过去就回来；只在雷鸣时每帧读闪光。**雷鸣照旧不下雨**：3D 没有雨粒子（以前就这样），正式画面的雷鸣层本来就没有雨
3. **酸雨的涟漪落在地台上**（`hd2d-wfx.js · rippleAt`）：正式画面的涟漪在整个战场随机位置冒出来，原样搬过来会飘在天上、远景上。现在每一下随机挑一个区、在它的地台顶面上随机挑一点（离不规则的外轮廓至少 0.6、深渊的洞口让开），按这一刻的镜头投到屏幕上（`HD2DFx.lens(sc.lensNow())`，和攻击演出同一个投影），落在画面外或者顶栏 / 技能栏底下就再挑，挑 8 次都不行这一下不落。**近景 / 特写只落在看的那个区**（别的区被景深糊掉了，2D 的涟漪糊不到，落在上面一清二楚反而不对）。地上的一圈斜着看是扁的：按镜头俯角压扁（高 × sin 俯角：远景 0.5、近景 0.41、特写 0.34）、越近越大（`WFX.ripple.size`：远 1、中 1.3、近 1.7、特写 2）——用单独的 `scale` / `translate` 属性叠在 weather-fx.css 的涟漪动画外面（`hd2d.css` 的 `.hd2d-wfx .wfx-acid b`），涟漪的画法、动画照旧，压扁 / 放大以后中心还在落点
4. **夜晚**：酸雨的涟漪也用正式画面的夜晚样子（更亮）
5. **减少动态效果**：照 weather-fx 现有的处理——不生成涟漪、不打闪电，雷鸣的云影、酷暑的热浪、微光的呼吸、相位的雾带都停住（weather-fx.css 的媒体查询）

### 已知的限制（这一条）

- 正式画面在这些天气下还会给界面面板换色（酷暑珊瑚红、酸雨酸绿、雷鸣深紫、微光青粉、相位李子紫，沙暴的面板里也飘沙雾），那些规则写在 `.g-app[data-weather=…]` 上；issue 只要战场上的那一层，原型的面板没换色
- 减少动态效果时，正式画面的酸雨换成几个画死在固定位置的静止圆环（weather-fx.css），照原样搬过来，所以那几个圈不一定在地台上
- 酸雨的涟漪是按冒出来那一刻的镜头放的，镜头正在过渡 / 拖动时，已经冒出来的那几个（1.6–4 秒）不跟着挪；压扁按这一段镜头的俯角，玩家自己把俯角拖得很偏时会差一点
- 2D 层是贴着画面的，后期的景深糊不到它（和铭牌一样）；雪、云影、雾带近景里会比 3D 场景清楚一点

## 主人试玩反馈 · 三续（issue #251）：沙暴还不够明显——要有旧画面那种翻滚的大团沙雾

> #240 把 `weather-fx.js` 套到了原型上，但桌面 1440×900 截图对比，沙暴还是比旧战斗画面弱很多：远景只有整体偏黄一点；近景只看得到几条很细的横线和零星沙粒；大团的沙雾基本看不见。

### 查下来的原因

- **颜色**：正式画面的沙雾是 (214, 164, 96) / (190, 132, 66)。旧画面画在浅灰的战场（`#e6e9ec`）上，一团团棕黄一眼就看得出；原型里画在沙黄的 3D 画面上，和地台的沙（`#d0aa6c`）、白天沙暴的雾色（`#d1a15e`）亮度都只差 2% 左右，几乎一个颜色，就看不见了。透明度、尺寸其实没被压低（远景 × 0.85）
- 正式画面那两层是「一阵一阵」的：每阵最后 35% 的时间几乎看不到
- 远景的中景剪影只往雾色靠 0.35（`veil`），离雾色还有晴天的一半，看得清清楚楚
- 3D 的沙线是 `LineSegments`，WebGL 里永远只有 1 像素，近景也粗不起来

### 改了什么

只改了 `hd2d-wfx.js` / `hd2d-weather.js` / `hd2d.css` 和测试；`weather-fx.css` / `weather-fx.js` 一个字没改，正式画面不受影响。场景相关的文件（`hd2d-scene.js` / `hd2d-backdrop.js` / `hd2d-layout.js` / `hd2d-world.js` / `index.html`）也没动。
