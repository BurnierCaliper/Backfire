# Antlerscale: Backfire（角鳞）

> 新加入的合作者先看 [ROADMAP.md](ROADMAP.md)：上手方法、合作约定、已完成的内容和接下来的路线。

同一套规则，三个入口：

| 入口 | 是什么 |
| --- | --- |
| `game.html` | 《Antlerscale: Backfire》Roguelike。标题界面 → 新的一局 / 继续 / 跑团模式 |
| `index.html` | 跑团版 · 规则计算器（主持人用） |
| `npm test` | 规则回归、无界面对打与真实转发服务测试；D3 全套测试需 Node 22+，先执行 `npm ci --prefix relay`。安装 Playwright/Chromium 后同时运行浏览器测试 |
| `npm run test:ui` | 必须真正运行的浏览器验收；缺少 Playwright 或 Chromium 时直接失败，不以跳过代替通过 |

R1 的范围、固定样本命令及评估证据见 [docs/r1/README.md](docs/r1/README.md)。评分公式、门槛和经验倍率保持原样，留待玩家测试后手动调整；文档与原始手册位于 `docs/`。

在线跑团的房间操作与验收边界见 [D3 说明](docs/d3/README.md)。转发服务独立部署到 Cloudflare Workers + SQLite Durable Objects；账号、免费额度、来源配置与部署步骤见 [转发服务部署](docs/d3/relay.md)。游戏网页仍为静态文件，单机不需要安装这些开发依赖。

## 代码分层（Roguelike 地基，M0）

```
界面      game.html · screens.js（界面切换）· game.js（战斗演出）· game.css
单局      rogue.js（流程规则）· rogue-ui.js（界面）· run.js（种子、遭遇）· save.js（存档）
战斗      sim.js（布置战场、无界面对打）· ai.js（敌人 AI）
规则      engine.js · party.js · enemies.js · growth.js · items.js · props.js · ledger.js · app.js · effects.js（第四章效果）· mods.js（单局武器图纸）
```

- **规则层不依赖网页。** `app.js` 里碰网页的地方都经由 `uiEl` / `hostValue`（在文件开头）：有网页时和原来完全一样，没有网页时（Node）返回空或读 `state.inputs`，画面函数直接跳过。所以同一份规则既能在浏览器里跑，也能在测试里跑。以后在规则里读网页元素，请用这两个函数，不要直接写 `document.getElementById`。
- **无界面对打（`sim.js · BattleSim`）。** `setup({ party, enemies | encounter, seed })` 布置战场，`run()` 自动打到分出胜负。敌人用 `ai.js`；玩家一方用可替换的 `policy`（默认：够得着就普攻血最少的，够不着就走近）。同一个种子整场结果完全一致。以后调数值可以批量跑同一场遭遇看胜率。
- **测试（`tests/`）。** `tests/headless.js` 把规则文件原样装进 Node 的隔离环境，每个测试一套全新的环境。`rules.test.js` 是修过的规则问题（柯尔特击破、过度自信、聚焦、不稳态、人数平衡、连带伤害……），`sim.test.js` 是 4 支队伍 × 6 种遭遇整场打完 + 种子可复现，`save.test.js` 是存档。改完规则跑一次 `npm test`。
- **界面切换（`screens.js`）。** 同一时间只显示一块界面（`title`、`battle`，之后的任务板、节点、休整、幕间都往这里注册）。战斗快捷键只在 `battle` 界面生效。
- **存档（`save.js · SaveStore`）。** 两份、各带版本号：`run`（本局，团灭或通关后删除）与 `meta`（跨局解锁、初始关系倾向）。只在节点之间自动保存；战斗中途退出，下次从这场战斗开头重来（种子保证开局相同）。改存档结构：`CURRENT` +1，并在 `MIGRATE` 写旧版升级函数。坏档另存为 `….broken`，不会直接丢掉。
- **单局流程（`rogue.js` 规则 · `rogue-ui.js` 界面 · `rogue-data.js` 数值）。**
  - **所有可调的数值只在 `rogue-data.js`**：每幕天数（8）、敌人等级曲线、区域与 BOSS 池、各种节点花的时间、开局物资、支线 / 主线模板、商店价目、工匠费用、升级奖励表。调平衡、换设计只改这个文件，规则代码不用动。
  - 一幕：开幕**自动接下主线**，本幕天数用完之前必须完成，否则本局结束。主线提前做完也不会马上打首领：继续做支线发育，**本幕天数用完时才迎战首领**（任务板上没有能接的任务时也会提前进入首领战）。任务板上挑支线，**天数不够的任务不能接**；接了会让主线来不及的支线会给出警告。任何战斗团灭，本局结束。
  - 任务内节点线性推进，**每个节点的类型都能看到**：战斗、精英战、休息（长休 / 短休）、商店（买水、食物、道具）、工匠（花奎支升级武器，单局里不要材料）。加一种节点：`ROGUE_NODE_TYPES` 加一行，`rogue.js` 写规则，`rogue-ui.js` 的 `NODE_PANELS` 加一个面板。
  - **敌人等级**：每幕从下限随天数涨到上限，首领 = 上限 + `bossLevelOffset`（现为 0；按代币抽随从的首领用 `bossEscortTokens` = 1 枚）；第 4 幕上限 15 级。通关后可以选择继续挑战额外幕（20、25 级）。
  - **经验**：击杀经验（手册表）+ 任务报酬经验都给；单局里升级所需经验为原来的 1/3。**升级按手册第三章**：4 级、8 级分配属性点（8 级不能加在同一项），5 / 10 / 15 级职责技能二选一（`growth.js · roleChoicesAt`），角色卡上到级解锁的技能自动获得；熟练项、专长等还没有系统的奖励先记在角色身上。
  - 单局期间把「队伍档案」（`ledger.js`）换成本局的，所以**耐久、力竭、长休吃什么、睡袋、维修工具包、水**这些手册规则和战斗原型完全同一套。离开单局时原样换回战斗原型的档案。
  - 每一步自动存档，「继续」接着玩；战斗打到一半退出，回来从这场开头重来。存档是第 2 版，第 1 版（M1）的存档会自动升级。
- **武器工匠与客制化图纸**（`rogue-data.js · ROGUE_SMITHS / ROGUE_SMITH_RULES / ROGUE_SMITH / ROGUE_MATERIALS`，效果在 `mods.js`）：
  - 工匠照设定是六位：“独眼”崔佛（外城区）、特蕾莎·特雷丝（ARMS）、“双面”泽卡尔（巨人城）、“愚人”季玛（沙漠）、摩尔玛（巨腕军火工业，很少见）、努尔 & 哈米德（第一采矿场，算一位）。每次做完任务回到任务板，按权重随机来 3 位不同的工匠（开局第一块板不来；设定里的所在地正是本幕区域的翻倍），任务里的工匠节点是随机的一位。
  - **升级价格照武器升级表**：每级要的材料按物品表折价（金属 1000、精炼合金 5000、聚合材料 10000、稀有晶体 50000、赫心结晶 100000）+ 5 级起的加工费（8000 … 20000），再 × `smithPriceScale`（1/6）。例：升 2 级 500、5 级 3300、8 级 15800、10 级 45000。
  - **各人的收费规则**：崔佛不帮陌生人，先「给他看看你的武器」才接活，在他那里升级满 3 次后关系变好打 85 折；特蕾莎对 ARMS 成员 8 折（单局还没有阵营，`armsMember` 先关着）；泽卡尔、摩尔玛标准价；季玛不收加工费，5 级起每次要帮他建庇护所 4 小时（算进距上次长休）；努尔 & 哈米德加工费 8 折但每次多耗 2 个最便宜的材料，而且装不了图纸。
  - **图纸**：在同一位工匠那里升级满 5 次（代替设定里的任务线），可以从他的两种客制化里挑一张（每位只能领一次）。在能装图纸的工匠处花 5000 奎支装到一把武器上，一把武器一张，装新的替换旧的。拿着这把武器时生效，武器人上场时作用在武器人身上。十二种客制化的具体规则见 `mods.js` 开头；「放弃角色自身的被动」按角色卡把十名角色的两个被动都接上了，放弃时按被动原文整个失效（例如川川不再积攒电能、柯尔特换不了刀头、绯秋一直拔刀），清单见 `mods.js · passiveOn`。
- **单局经济规则（`rogue-data.js · ROGUE_CONFIG` 的「经济」段）**：任务之间的休整等于回到城里，可以买补给；任务报酬与委托方补给按人数给（模板是 2 人队的量）；奎支报酬随幕数 ×1 / 1.2 / 1.4 / 1.6（额外幕 1.8 / 2.0）；工匠费用为手册参考价 × 1/6；敌人掉落统一按杂兵 80 / 精英 460 / 首领 920（手册各档最高掉落 × 0.4，让任务报酬始终是收入大头、掉落不超过一半；战斗原型仍按手册逐个敌人算）。
- **诊所（回城休整时，或任务里的诊所节点）**：按缺的血量收钱治疗；**义体改造**把肉体换成别的血量层（规则在 `growth.js` 开头）：肉体 8 : 装甲 7 : 护盾 6 : 沙尘 6，可换的肉体 = 义体改造率 × 肉体上限；也可以把剩下的肉体按 8 : 7 全部换成星灵（不受改造率限制）。最多 3 种血量，内层必须是肉体或星灵其中一种，排列从内到外是 肉体 / 星灵 → 装甲 → 护盾 → 沙尘。改造方案记在角色身上，每次按等级重算血量时照方案重建，所以升级后依然有效。价格在 `ROGUE_CLINIC`（每改动 1 点肉体 200 奎支，治疗每点 60，占位）。
- **实战测试（`node tools/playtest.js [种子] [队伍]`）**：用一套比朴素打法聪明的策略打完整一局（四幕）：每次行动前把能用的技能 × 目标（含分步选择、危墙和配置物）在状态副本上按「顺利 / 不顺」各预演一次，按评分增量、我方掉血、施加状态、打掉危墙挑最好的；局势崩了就撤退；单局决策（接任务、战前休息、补给、工匠、诊所、检定、升级）也按合理玩家的思路。输出每场战斗的结果、评价、战前战后血量、个人数据，以及报错、日志里的 NaN / undefined、打不完的战斗。`TRACE=1` 打印每一步的决策；`BOSSTEST=幕:等级` 只打那一幕的首领。
- **评分验算（`node tools/score-by-act.js [每格场数]`）**：按单局的真实流程（遭遇、敌人等级、战场配置、天气）逐幕打普通 / 精英 / 首领战，单人和 2 / 3 / 4 人队各若干场，列出胜利场次的得分分布（平均、p25、中位、p75、p90、每人分）、回合数，以及现在「得分 ÷ 敌人基准」的评价分布。角色等级、武器等级等假设写在文件开头。每格 60 场约 1.5 分钟。
- **经济验算（`node tools/economy.js [局数]`）**：用真实的单局规则把 2 / 3 / 4 人队各跑若干局（战斗一律判胜，只看钱和补给），按幕列出任务报酬、掉落、委托方给的补给、水 / 食物 / 维修 / 升级的花费、长休吃没吃上、最高连续清醒小时数、幕末余额。改完 `rogue-data.js` 的数值跑一次就能看到效果；也可以不改文件直接试：`ECO_SET='{"smithPriceScale":0.25}' node tools/economy.js 40`。
- **所有模式共用的手册规则**（`app.js` / `ledger.js`）：
  - **武器耐久**（手册第五章）：一场战斗结束 −1，武器人被击败 −2，发动格挡 −1，长休回满，耐久 0 无法使用。
  - **坚毅生命对玩家不可见**（玩家手册第二章）：游戏版（`GAME_MODE`）的单局面板、休整面板都不显示坚毅，长休、撤退、自焚只说「恢复了一些 / 被消磨了一些」，不给数字；主持人计算器和后台照常显示。
  - **濒死**：战斗结束后恢复到 1 点生命（起身靠坚毅撑着的也一样）。
  - **武器人伤势**跨战斗保留，长休痊愈；上一场倒下的武器人长休前唤不出来。
  - **力竭**：距上次长休 20 小时不能用坚毅起身，40 小时 atk −3 def −1，60 小时击倒即死，80 小时死亡。战斗里读 `state.exhaustTier`，单局按小时数设置（战斗原型目前不设）。
  - **撤退**（主持人手册第七章）：按「全员完好 / 有损伤 / 半数倒地」三档扣时间、坚毅、奎支 / 道具，需要时一人断后挨一次无法格挡的攻击。表在 `app.js · RETREAT_RULES`（「一部分奎支」手册没给比例，暂定 25%）。单局里撤退 = 跳过这一站；首领战不能撤退。
  - 测试 `tests/rogue.test.js` 覆盖以上规则，并会自动把整局打完（朴素打法），检查流程走得到底、同种子过程一致、存档读回来结果不变。
- **已定规则在存档里的体现：** 开局队伍 2–4 人；减员到 1 人时敌人不做特殊调整（人数平衡按 2 人基准）；每名角色和自己的专属武器人记在一起（绯秋两把刀），`SaveStore.killHero` 让角色永久死亡时连同武器人一起离开队伍。

# Anterscale · 伤害与状态计算器

打开 `index.html` 即可使用（用浏览器双击，无需安装）。

## 用法

1. 上方选区制、队伍人数、天气。
2. 用「从预设添加」放入敌人，或「新增单位」手填玩家。
3. 点单位：先点攻击者（绿框），再点受击者（红框）。
4. 填 ATK、倍率、骰子、属性、基础击破，勾需要的词条。
5. 点「计算这次攻击」看分层结果；「应用到受击者」会改血条和架势。

队伍人数缩放在「从预设添加」时先按当时的人数算一次；点「开始战斗」时会按我方实际上场人数（2–4，不含武器人）把敌人的血量与架势重新换算一遍（`engine.js · rebalanceEnemiesForParty`），开战前增减队员也能对上。开战之后不再自动改。

回合开始 / 结束按期望值结算火场、灼烧、腐蚀、沙尘恢复、护盾回满等。需要掷实际骰时，把攻击区的骰子用法改成「现在掷骰」。

# 跑团模式（game.html）

标题界面点「跑团模式」进入，给主持人带跑团用。**一切数值照原手册**，不用单局（Roguelike）的折算：正常经验曲线、敌人按手册逐个掉落、物价与武器升级照手册物品表 / 武器升级表（`trpg-data.js`）、没有工匠客制化、力竭按距上次长休的小时数进战斗、坚毅生命对主持人照常显示。

分两个环节，主持人随时切换：

- **探索环节**（`trpg-ui.js`，规则在 `trpg.js`）：顶栏是天数、距上次长休的小时数（带力竭提示）、奎支、水、食物。左栏是队伍状态（血量、坚毅、经验、未分配属性点、每把武器的等级和耐久）。中间五页：
  - **队伍**：勾选参加的角色；发经验（全员或指定一人，自动升级）；4 / 8 级的属性点在这里分配；清空队伍记忆重新开团。
  - **时间与休息**：+1 / 2 / 4 / 8 小时或任意小时数；全员或单人短休；长休（选时长、每人吃什么，扣水和食物；也可以「不扣补给」）；主持人全员复原。
  - **商店**：手册物品表全部商品，「买」扣奎支、「给予」是主持人直接给（战利品、奖励）。
  - **背包**：手动加减奎支和水；探索中用医疗包、维修工具包；每样物品 ±1。
  - **武器升级**：每把武器下一级要的材料和工匠参考费用；4 级以内可以在工作站自己升（只耗材料），更高要找工匠（材料 + 费用，费用可改），或主持人直接升。
  - **后台**（顶栏「后台」按钮也能直接跳过来）：给叙事用，不走任何规则。直接改天数、距上次长休的小时数、奎支、水；每个角色的状态（正常 / 起身中 / 濒死 / 死亡）、各层血量、坚毅、等级、经验、属性、未分配属性点、今天已短休次数；每把武器的等级、耐久，治好武器人的伤势。填完点「应用改动」一次写入，可以写原因，每项「原值 → 新值」都记进探索记录。数值会夹在上限之内；把血量 0 的角色改回「正常」会自动给 1 点血。
  - 右栏「探索记录」记下每个操作，可以复制。
- **战斗环节**：顶栏「进入战斗环节」切到战斗画面，照常配置遭遇、开打。打完结算后点「回到探索环节」（或战斗顶栏的「探索环节」；没打完就回去会放弃这场战斗）。

**存档**：点「跑团模式」先到选存档的画面，有 3 个空位，每个放一个团（`trpg.js · trpgReadSlots / trpgWriteSlot`，界面在 `trpg-ui.js · renderSlots`）。空位里是这个团的队伍、等级、经验、武器等级与耐久、背包、奎支、时间、探索记录和上次的遭遇。玩的时候每个操作、每场战斗结算都自动存进当前空位，不用手动存；探索环节顶栏「换存档」随时换团。每个空位可以改名、删除、「存成文件」备份（JSON）、「从文件读入」。存档在本机浏览器里，换电脑或清浏览器数据前先存成文件。旧版只有一份的队伍记忆，第一次打开时会放进空位 1。跑团模式下战斗顶栏的「存档」按钮藏起来，统一用这里的空位。

## 战斗画面

战斗画面就是原来的战斗原型。需要鼠标。计算器 `index.html` 照常可用，两边共用同一套规则文件。战斗顶栏的「标题」按钮回到标题界面。

## 操作

| 操作 | 方式 |
| --- | --- |
| 选技能 | 点技能按钮，或按数字键 1–9 |
| 预览 | 选好技能后把鼠标移到目标上 |
| 出手 | 左键点目标 |

预览颜色：闪白＝会被打掉的血量和架势（淡白＝骰子大时才会打到的部分）；金光＝会造成失衡；蓝光＝冰属性击破造成失衡（冰冻）。骰子按最小、最大各预演一次，格挡等随机判定按失败预演。

## 结构

- `game.js` 只做表现：记录事件、沙盒预演、逐步播放、按顺序演出敌人行动、格挡与协助选择。规则一行都不在里面。
- 敌人 AI 的决策在 `ai.js`（`EnemyAI`），战斗画面和无界面模拟共用。
- 规则仍然全部来自 `engine.js / party.js / enemies.js / growth.js / app.js`。改规则只改这些文件，游戏自动跟着变。
- `game.html` 里藏着一份计算器界面（`#calc-core`），因为 app.js 会读写这些元素。**如果改了 index.html 的结构，运行 `python tools/build_game_html.py` 重新生成 game.html。**
- 游戏不会读写计算器的存档。

## 原型范围

- 固定遭遇：实况组四人 vs 狂徒（匕首）、狂徒（锤）、强盗头子，右上角可选敌人等级。
- 敌人 AI 覆盖全部杂兵、精英，以及三个 BOSS（亡命之王、飞碟触灵、沙灵聚合体）。指挥官（赤牙等）尚未接入，仍需手动操作。

### 敌人 AI 怎么改

行为写在 `ai.js` 的 `AI_SPEC` 表里，一个敌人一行，加新敌人就加一行：

| 字段 | 含义 |
| --- | --- |
| `dist` | 想和目标保持的距离。`0` 贴近，`1` 远距离（3 区制下太远会接近、太近会后撤），`null` 不主动移动 |
| `aim` | 打谁。`local` 同区优先（手册没写明追谁的都用这个）／`lowest` 血量最低／`nearest` 最近／`topAtk` ATK 最高 |
| `near` `far` | 同区、隔区分别用哪个技能 |
| `special` | 需要单独判断的（自爆、召唤、阶段、命令等），实现在 `aiSpecial` |

行为规则：

- **主动接近的**：同区已经有人就直接打同区，不追别人。例外是手册写明追谁的（穴鸦、空投蜂群追血量最低；安保巡逻车追 ATK 最高；强盗头子在场时狂徒集火最低血量）。
- **主动远离的**：优先后撤到没有敌人的区；退不掉才近战。
- **3 区制**：远距离敌人统一保持距离 1，太远接近、太近后撤。
- **嘲讽**：随机攻击也会被吸。飞碟触灵踩踏随机打两人时，嘲讽固定吃掉其中一击，另一击仍随机。被嘲讽的远距离敌人不后撤。
- 属性专属攻击效果的「挂载」按钮暂时隐藏（原型没有效果位）。
- 伤害数字、场地底色、天气界面配色与计算器一致；单位多时铭牌会自动缩小。

```js
kit: (u) => ({ zone, label, ready })   // 也可以返回数组表示多个区，返回 null 表示当前没有预警
```

| 字段 | 含义 |
| --- | --- |
| `zone` | 要打的区 |
| `label` | 区域上显示的短标签 |
| `ready` | true 表示这回合就会落地，红框会闪烁 |

目前已登记：机甲触灵（榴弹）的榴弹标定与待发、飞碟触灵的自爆待发、沙灵聚合体的电能炮蓄力、自爆小车的引信已到、赤牙的霰弹预热。

## 后台

顶栏「后台」按钮，或「队伍配置 → 打开后台」。可以改等级、经验、六维属性、武器等级、武器耐久、坚毅生命，也能发放经验。改完立刻在战场生效，用来测试不同等级下的伤害。

渲染逻辑就是计算器那一份（`app.js · renderBackstage`），游戏只是把它的容器搬进自己的面板，所以两边永远一致。

角色卡带 `enName` 字段（Rabbie / Yuhito / Akari / Hiaki 等），只用于显示；内部的 `kit` 标识没有改，存档和技能 id 不受影响。

## 新角色：诺拉 / 维塔斯

在「队伍配置」里加入。三个专属机制写在 `app.js`，都是通用写法，以后要改只改这几个函数：

| 机制 | 实现 |
| --- | --- |
| 刺入 | `piercedTarget` / `setPierce` / `clearPierce`。一次只能刺一个，刺新的解除旧的，与诺拉距离 >1 自动断，目标倒下也断。状态栏显示「刺入」 |
| 双相冲动 | `noraMood` / `setMood` / `flipMood`。开战随机，每回合开始 1/3 翻面，击杀后翻一次，安抚强制温和，压力升高强制下回合残忍 |
| 冷气注射 | `noraFrost`。目标已有冻伤时，改为一次 1d4+诺拉等级 的冰伤 |

已有系统直接复用、没有另外实现的三个技能：**激活**（异常职责 1，Lv1）、**传播**（异常职责 2，Lv10）、**应急处理**（生存职责 1，Lv5，效果与卡面完全一致）。

### 两处按理解处理的地方

- **对刺入目标出手不受「距离 1」限制**（`engine.js · SKILL_RANGE` 里的 `nora_aa` / `nora_needle`）。因为温和的发射针尖会把诺拉移到目标同区，若仍按距离 1 判定，她反而打不到自己刺入的目标；而刺入超过距离 1 本来就会自动断，所以刺入目标必然在距离 0–1 内。没有刺入时仍严格要求距离 1。
- **普通攻击在温和状态下对刺入目标只治疗、不造成伤害**，因此刺入也能扎在队友身上当治疗手段，发射针尖允许选友方（提示里写「任意单位（含友方）」，游戏界面据此放开选择范围）。

## 队伍档案：跨战斗记录（ledger.js）

跑团用。战斗之外的状态都存在这里，和等级、经验、背包一起进入队伍档案，跟随存档位与本地保存，刷新页面不会丢。

### 跨战斗保留

- 角色的**当前血量、坚毅生命、濒死/死亡**不再每场回满，下一场开战时照原样带进去。
- 每把武器的**耐久**，按手册第六章自动结算：

| 事件 | 耐久 |
| --- | --- |
| 一次战斗结束 | 队伍里每把武器 −1（不论是否唤出过） |
| 武器人在战斗中被击败 | −2 |
| 发动格挡 | −1（**空手格挡不扣**） |
| 长休 | 恢复全部 |

耐久为 0 的武器无法使用：持在手里的会被放下（绯秋改持另一把刀，其余角色变空手），武器人无法唤出。

### 背包（顶栏「背包」）

分四块，每项都能直接增减，方便主持人记录战利品、交易、赠送：

- **奎支**、**水**（毫升）：输入数额点「加」「减」
- **食物**：流食 / 罐头 / 有机 / 美食，四档都列出，数量为 0 也显示
- **物品**：战斗道具与补给。维修工具包可在这里修指定武器（+10 耐久），医疗包可在战斗之外对指定角色使用。底部下拉可添加任意物品。

战斗里「使用道具」只列能在战斗中用的物品，食物、维修包、睡袋不会混进去。

### 休整（顶栏「休整」）

战斗进行中不能休整（背包仍可增减）。

- **时间**：第几天、距上次长休多少小时、力竭档位（20/40/60/80 小时）。可手动推进 1/4/8 小时，每满 24 小时刷新短休次数。
- **队伍状态**：每人的血量、坚毅、每把武器的耐久，一眼看全。
- **短休**：恢复 等级×2+体质，一天两次（熊兽人一次）。川川「活力源泉」+25%。每次推进 1 小时。
- **长休**：时长 8–12 小时可选，**睡得越久坚毅恢复越多**（每小时 +2）。每人选吃哪种食物，面板实时显示水和各类食物的需求与库存，不够时按钮变灰。
  - 食物额外坚毅：罐头 +1、有机 +2、美食 +5，按吃的份数计。
  - 睡袋：每个睡袋让一人每小时坚毅 +1（不消耗）。
  - 长休后：血量回满、清除濒死、全部武器耐久回满、短休次数刷新、进入下一天。
  - 勾选「主持人强制」可以不扣补给。
- **主持人：全员复原**：不扣补给、不推进时间，直接回满血量、坚毅、耐久（测试或剧情需要时用）。

每一次增减、休整、耐久变化都会写进右侧记录，方便事后核对。

## 单局层（run.js）

Roguelike 的地基，和战斗规则完全分开。战斗规则仍然全部在 `engine / party / enemies / growth / app` 里，`run.js` 一行规则都不含。

### 1. 种子随机数

`RNG.install(seed)` 把 `Math.random` 换成以种子决定的序列，规则代码不用改一行。同一个种子必定跑出同一局；`RNG.draws()` 记录已抽取次数，读档时用 `RNG.restore(seed, draws)` 把随机流拨回原位。

出手预览不消耗随机流：预览本来就会临时接管 `Math.random` 再还原，所以看多少次预览都不影响结果。

```js
RUN.start({ seed: "ABC123" });   // 不给种子就自动生成一个
```

### 2. 随机遭遇（代币制）

每场战斗 4 枚代币：**杂兵 1 枚，精英 2 枚**。所以一场是 4 杂兵 / 2 精英 / 1 精英 + 2 杂兵。空投蜂群三只一组，整组记 1 枚。

- **5%** 概率这场变成 5 枚代币
- **5%** 概率无视阵营限制，变成混战

敌人数据写在 `ENEMY_INFO`：阵营、出没区域、代币、成组数量。

| 阵营 | 成员 | 区域 |
| --- | --- | --- |
| 安保 | 机器人看守（剑/枪）、安保巡逻车、自爆小车、巡检浮标、投料无人机、空投蜂群、高压巡逻艇、播撒者 | 外城区 / 巨人城 / 矿场 |
| 警卫队 | 警卫队队长 狼 / 牛 / 蜥蜴 | 巨人城 / 外城区 |
| 盗匪 | 狂徒（匕首/锤）、强盗头子、亡命之王 | 外城区 |
| 沙灵 | 沙灵（四足/人形）、大沙灵、活沙、扬尘体、沙灵聚合体 | 沙漠 |
| 触灵 | 机甲触灵（机枪/榴弹）、飞碟触灵 | 天网设施 / 巨人城 |
| 巨人 | 巨人 | 巨人城 |
| 野生 | 穴鸦 | 外城区 / 沙漠 |
| 古代造物 | 观测鸦 | 沙漠 |

`ALLIED_FACTIONS` 写明可以同场混编的阵营，目前是「安保 + 警卫队」。

```js
rollEncounter({ region: "外城区" })          // 随机一场
rollEncounter({ region: "沙漠", faction: "沙灵", tokens: 5, mixed: false })
rollBossEncounter("outlaw_king", { region: "外城区" })  // BOSS 不占代币，随从另给 2 枚
```

区域还带默认天气倾向：沙漠 60% 沙暴、矿场 40% 酸雨、巨人城 30% 雷鸣。站位按远程/飞行靠后自动排。

实测 2000 场（外城区）：五代币 5.1%、混战 3.9%、无超预算、无跨阵营错误。组合分布 1+1+2 占 43.8%、1+1+1+1 占 42.4%、2+2 占 8.8%。

### 3. 固定遭遇（ENCOUNTERS）

战斗不再写死在 `setupBattle` 里。一场战斗就是一条数据：

```js
{ id, name, region, tier,            // tier: normal / elite / boss
  zoneMode: 2 或 3, weather, fields,
  enemies: [{ preset, zone, count, level }] }   // level 可写 "+1" 表示相对遭遇等级
```

目前有 10 条外城区遭遇（4 普通、3 精英、3 BOSS）。开战方式：`GAME.setupBattle(等级, "遭遇id")`；不传遭遇则沿用原来的默认阵容。加遭遇只要往表里加一条，不用碰代码。

### 4. 单局状态（RUN）

和「角色档案」（等级、经验、属性，跨局保留）分开，只存一局之内会变的东西：

| 内容 | 说明 |
| --- | --- |
| 血量 / 坚毅生命 | 跨战斗保留，不再每场回满 |
| 武器耐久 | 每场战斗 −1；武器人是战斗中才唤出的，所以在唤出那一刻补回上次的耐久与血量 |
| 补给 | 水、食物、奎支 |
| 天数与时长 | 用来算力竭 |

### 5. 休息（按手册）

- **短休**：恢复 等级×2+体质 点血量，一天两次（熊兽人一次）。
- **长休**：全回血、补满短休次数、武器耐久回满、shp 每小时 +2（8–12 小时）。按种族支付水与食物，四人队约 3750 ml 水 · 8 份食物；补给不够则只能消磨时间。
- **力竭**：20/40/60/80 小时四档，按手册。

起始补给默认 5000 ml 水 · 10 份食物，够四人队做一次长休还剩一点余量。

### 6. 批量测试

有了种子和遭遇数据，就能批量跑同一场战斗统计胜率。实测（实况组四人，随机决策机器人，各 8 局）：

| 遭遇 | 等级 | 胜率 | 平均回合 | 平均坚毅损失 | 平均倒地人数 |
| --- | --- | --- | --- | --- | --- |
| 外城区巷战 | 1 | 63% | 8.9 | 20.4 | 1.9 |
| 巡逻队拦截 | 1 | 100% | 5.3 | 0 | 0 |
| 沙灵游荡 | 1 | 100% | 7.3 | 4.5 | 0 |

这些数字只适合横向对比（改规则前后、不同遭遇之间），机器人是随机决策，不代表真人玩家的难度。

## 亡命之王（主持人手册第十章）

- **一回合一动**：首领没写「一回合几动」就是 1 行动点；只有指挥官（赤牙）是 3 行动点 + 1 附赠。之前亡命之王被误设成 3 行动点，这是首领「太难」的主因。
- **固定随从**：强盗头子、匕首狂徒、锤狂徒各一，和他同区（`run.js · ENEMY_INFO.outlaw_king.escorts`，不按代币抽；三区战场也不拆开）。
- **护卫**：对他的单体攻击由同区其他狂徒承受（挑血最多的那个）；范围攻击照常波及他。被挟持时失效。
- **攻击命令**：所有狂徒改打被命令的人。强盗头子会主动走到王所在的区。
- **哗变**：强盗头子血量 ≤ 25%、与王同区、同区没有其他狂徒时，抓住王：王无法行动、易伤 25%；狂徒只能反水打强盗头子，只打 1d6 物理（不加 atk，每十级升一档骰），不在同区会先走过去。回合开始、每个敌人行动前、狂徒阵亡时都会检查条件。强盗头子死 → 王恢复行动；王在被挟持时被杀 → 强盗头子继位，atk / def 翻倍，狂徒不再反水。

测试：`tests/king.test.js`。

## 效果系统补全（effects.js）

对照玩家手册第四章补上之前没实现或只做了一半的效果，规则都写在 `effects.js`，`app.js` / `engine.js` 在对应时机调用：

- **刺骨**：施加时立刻对肉体 / 星灵 / 沙尘层造成该层上限 10% 冰伤；被击破时再来一次；受到火属性伤害时立刻解除并对内层造成 10% 火伤。
- **过载**：护盾当回合翻倍，下回合开始清零并结束，再下一回合按规则回满（之前护盾每回合都被清零且过载永不结束）；期间被击破会爆炸（等级 × 1d4）；过载装甲受近距离攻击反伤 50%。
- **熔融**：护盾一回合内累计受到上限一半的伤害就失效，下回合以一半恢复。
- **霜结**：冰攻击恢复 1 架势；免疫冻伤；再次霜结到下回合前完全免疫伤害。
- **溅射**：酸属性单体攻击对同区其他敌人 25% 溅射；移动扣 15% 最大生命；免疫腐蚀。
- **导体**：每三次攻击的第三次额外打一个随机敌人（雷暴天气两次一跳）；免疫感电；移动不耗附赠；架势上限 3。
- **千钧**：格挡 +10%（之前误写成 heavy 键没生效）；免受位移；无法恢复架势。

- 柯尔特「更换刀头」的追击射程（`app.js`、`engine.js · SKILL_RANGE`）：追击伤害的射程写死成近距离，换成酸液炮（远距离）之后那一击打不到距离 1，被动等于失效。现在射程跟着换上去的新刀头走，外层判定放宽到 0–1，由技能内部按新刀头判定。

- 职责技能统一（`party.js`）：角色卡上与职责技能同名的条目，本质就是那个职责技能，按手册第六步的职责表裁定，不再各自实现一份。改动：
  - 职责表补齐了原本缺的两项**技能一**：直伤·准备、坦克·嘲讽。以前只有夕夏和灯自己有，别的同职责角色到了等级也拿不到。

- 射程判定的两处回归修正（`app.js · dealTo`）：
  - **玩家不再用角色卡上的 `range` 兜底**。玩家技能的射程由技能自己决定（提示文字或 `SKILL_RANGE`），`runSkill` 已经判过一次；再用角色卡兜底会误伤，比如诺拉卡上是远距离，她的空手攻击、近战技能全被当成只能打距离 1。现在只有敌人用单位卡的 `range` 兜底。
  - **借机攻击不再做距离判定**。借机是目标已经离开那一区之后才结算的，此时距离必然是 1，再判一次必然判错。借机、协助、格挡这三类反应本来就由触发条件限定了位置，统一跳过射程与飞行附加代价。借机用的标记是 `flags.opportunity`。
- 空手攻击统一为同区（`engine.js · SKILL_RANGE · bare_aa`）。


- 攻击射程（`app.js · dealTo` + `enemies.js · ENEMY_SKILL_RANGE`）：射程原本只对玩家技能生效，敌人完全不检查，所以标了远距离的敌人（人形沙灵、机器人看守（枪）、机甲触灵（榴弹）、警卫队长·蜥蜴等）在同区照样能打。现在按手册统一判定：近距离仅距离 0，远距离仅距离 1，任意距离 0–1。范围攻击和反应类（协助 / 借机 / 格挡）不受此限。

  射程是**按技能**判定，不是按单位。远距离敌人往往另有近战手段（机器人看守的近距砸枪、机甲触灵的近距枪管、亡命之王的处死命令等），这些写在 `ENEMY_SKILL_RANGE` 里，优先于单位卡上的 `range`。加新敌人技能时若射程和单位默认值不同，往这张表加一行。
- 川川普通攻击改为近距离（`engine.js · SKILL_RANGE`）。
- 飞行单位的近程惩罚（`app.js · dealTo`）：近程攻击飞行单位需额外消耗 1 附赠行动，付不起就打不到。敌我同规则。三个例外：范围攻击、杂兵敌人、以及飞行单位打飞行单位。
- 敌人默认目标（`ai.js · aiTarget`，原在 game.js）：手册没写明追谁时，改为倾向攻击血量最高的玩家角色或武器人。手册写明的仍然照旧（穴鸦、空投蜂群追最低血量，强盗头子追最弱，安保巡逻车追 ATK 最高，嘲讽与决一死战优先）。
- 高压巡逻艇（`enemies.js`）：原本有电弧扫射和感电装置两个技能，一回合能打两次。按手册它只有电弧扫射一种攻击，感电是这一击的附带效果。现在合并成一个技能：对距离 1 的所有敌人造成电伤，并对其中一人施加感电；同时补上了范围攻击标记（原本这个 AoE 是可以被格挡的）。


- 焰袭（`engine.js · SKILL_RANGE` + `app.js`）：提示里的「与夕夏不同区」被射程解析当成了「同区」，于是要求目标必须和柏妮尔同区，敌人在夕夏那一边时完全打不出去。现在射程改由技能自己判定：焰袭是收回武器后由夕夏结算，所以要求目标距离夕夏 ≤1。

- 加压灌输（`app.js`）：温和治疗每五级多一个 d4（2d4 → 3d4 → 4d4）。
- 角色资源显示（`game.css`）：一个区里单位多到需要缩小铭牌时，会把角色资源那一行整行藏掉，引擎启动、电能、双相这些就看不见了。现在改成缩小字号继续显示，不再隐藏。
- 战斗结算后查看日志（`game.js`、`game.html`）：结算面板加了「查看日志」，点了会收起面板，战场和右侧记录都留着可以翻；右下角出现「返回结算」随时回去选再来一局。

- 双相与刺入归属武器系统（`app.js`）：原本只记在诺拉身上，诺拉不在场时读不到，维塔斯面板也看不到当前是温和还是残忍。现在诺拉和维塔斯两边同步，分出维塔斯时从诺拉那边带过去，之后任何一边变化都会同步；维塔斯的面板也会显示双相状态和刺入目标。


- 激活（`app.js · activatableStatuses` / `triggerOneStatus`）：原本只认灼烧、震荡、高能、腐蚀四种，漏了冻伤和感电，所以对着只有冻伤的敌人按下去什么都不会发生（诺拉的套路正好全是冻伤）。现在：
  - 六种状态都能激活：灼烧、感电、腐蚀、冻伤、震荡、高能。
  - 选目标时只列身上确实带状态的敌人；全场都没有时按钮直接变灰。
  - 目标身上有多种状态时，会再弹一次选择，让你指定激活哪一种。
  - 每种的效果与「触发一次该状态的回合结束结算」完全相同：灼烧一次性触发全部层（并和回合结束一样叠 1 层，酷暑 +2、雪天不叠），冻伤触发一次击破（酷暑下触发后结束），感电走感电脉冲，腐蚀按有无装甲取骰，震荡 1 击破，高能按高能值打能量伤害。


- 维塔斯的双层成长（`growth.js`）：武器人原本只能有一条血层随等级成长，维塔斯是装甲每级 +1、护盾每级 +4，所以给 `WEAPON_GROWTH` 加了 `extra` 字段支持第二层。
- 角色阵亡的呈现（`game.js`、`game.css`）：玩家角色阵亡时弹出提示框，需要确认才继续（写明是谁、还剩几人）。角色不再淡出离场，而是留在原地变成灰色并标「倒下」，下方角色选单里也保留一个灰条，避免打着打着忘了少了谁。敌人仍旧淡出离场。武器人倒下同样留在场上变灰，但不弹提示框。

- 内层血量（`engine.js`）：内层标记现在写在血量层对象本身（`layer.inner`），而不是靠「数组最后一个」判断。错位会交换血层顺序，原本会导致被翻到外层的内层血量打穿后不结算死亡。现在不管顺序怎么变，内层归零就是死亡（玩家角色进入濒死）。
- 即时效果单回合（`app.js · beginRound`）：熔融、刺骨、扩散、折射原本只在被用掉时才清除，没用掉就会一直留着。现在和错位一样，回合开始时统一失效并写进日志。
- 武器人唤出（`app.js · SKILL_REQUIREMENT`）：武器人阵亡后仍留在场上数据里，再唤出会被判成「已经在场上」，既不出现也白扣行动点。现在分清「已在场」和「本场已倒下」，两种都在扣费前拦下并写明原因。绯秋分出刀的选项里也只列真正能分出的那把。

- 范围攻击不可格挡（`app.js · dealTo`、`engine.js`）：敌我双方都一样，带 `aoe` 标记的攻击不再触发协助格挡，也不触发敌人的自动格挡（牛队长、安保巡逻车）。
  带溅射的攻击（银翼普通攻击、银翼协助攻击）：主攻击被格挡就不产生溅射；溅射本身带 `aoe`，无法被格挡。攻击结果新增 `blocked` 字段供判断。以后再写这类技能，照 `wing_aa` 的写法接住主攻击的返回值判断 `res.blocked` 即可。

- 技能使用前提（`app.js · SKILL_REQUIREMENT`）：像一闪「仅居合」这类条件原本写在技能体内部，等行动点扣完才判断，结果条件不满足时按钮照样能按、行动点照样扣。现在统一抽成一张表，在扣费之前检查，不满足就不扣行动点也不消耗资源；游戏界面读同一张表，把按钮变灰并写出原因。

  已登记：一闪（仅居合）、热锅（仅丹生谷）、冰美式 / 意式浓缩 / 酸萃（需咖啡液）、嘲讽（每场次数）、处决 / 全速撞击（需引擎）、焰袭（需夕夏引擎且不同区）、铁壁 / 磁场盾 / 雷电风暴（需电能）。加新技能就加一行：`id: (a) => 不满足时返回原因，满足返回 null`。只放与目标无关、只看行动者自身的条件。

- 酸萃（`app.js`、`party.js`）：每五级多一个 d4，治疗和伤害各自独立掷（1d4 → 2d4 → 3d4 …）。提示文字跟着等级显示。
- 掩护（`app.js · statusLine`）：掩护状态原本只写在 `coverBy` 字段上，任何界面都看不到，游戏的出手预览因此判定「这一下没有效果」，导致掩护无法选中目标。现在掩护会显示在状态栏（「掩护（川川）」），计算器和游戏都能看到，预览也能识别。
- 出手预览（`game.js · previewOf`）：天气和场地的变化也算作有效果，制冰机、酸萃这类只改环境的技能不会再被判成无效。
- 冰美式（`app.js`、`party.js`）：改成每五级升一档骰面（2d4 → 2d6 → 2d8 → 2d10 → 2d12），骰子个数固定 2 个。原本写的是每五级多加一个 d4（2d4 → 3d4）。技能提示里的骰子也会跟着等级显示。
- 冰冻加伤（`engine.js · applyResultToUnit`、`app.js` 冻土与通用击破）：只有把目标**打进**失衡的那一击是冰属性才挂「下次受击第一击 +50%」。原本判断的是「打完之后架势 ≤ 0」，所以对着已经失衡的目标再用冰属性攻击会反复重挂。三条路径（攻击、走进冻土、其它来源的击破）都改成同一个判定：这一下之前架势 > 0 且还没失衡。
- 濒死规则（`engine.js · isDownProtected` + `app.js`）：
  - 濒死单位在玩家自己按下「起身」之前不受任何伤害。攻击、协助、借机、状态与场地持续伤害都一样，敌人攻击它时连格挡询问都不会弹。
  - 濒死单位不再触发敌人的协助攻击。
  - 进入濒死时解除晕眩（同时清掉不稳）。
  - 濒死单位不能直接协助格挡，但可以「起身并协助格挡」：选它格挡会先起身再照常结算，之后受伤改打坚毅生命。格挡弹窗里会标出来。
- `app.js`：`weaponCardName` / `setOwnedWeaponLevel` / `renderBackstage` 原本写在 `init()` 内部，只有计算器自己能调用。移到顶层，游戏页面才能复用同一份后台。行为没变。
- `enemies.js · ZONE_THREATS`：新增通用区域预警（见上）。计算器原本写死只认机甲触灵的榴弹，现在改读这张表。
- `engine.js · SKILL_RANGE` + `app.js` 射程检查：技能射程原本只从提示文字里解析，先移动再作用、或同区与距离 1 都允许的技能会被误判。现在这类技能在 `SKILL_RANGE` 表里写明射程，优先于文字解析。目前有两条：圣战起始（灯，0–1，先移动 ≤1 再对到达后的同区敌人施加错位）、猛扑（年糕，0–1，跃向距离 1 的敌人或带走同区敌人）。以后再遇到文字说不清射程的技能，往这张表里加一行即可。
- `enemies.js · ufo_stomp`：踩踏的随机两名目标会被嘲讽吸走其中一击（另一击仍随机），之后消耗嘲讽。计算器和游戏同时生效。
- `app.js · spawnWeapon`：武器人在同一场战斗内血量继承。收回后再唤出，沿用上次的血量层，并移除旧的隐藏单位（以前会生成满血的新单位，旧单位残留在 state.units 里）。上次收回时血量为 0 则无法唤出。计算器和游戏同时生效。
